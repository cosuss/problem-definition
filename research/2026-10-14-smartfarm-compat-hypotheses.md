# 스마트팜 호환 문제: 번호별 문제정의 가설 1~5

작성 2026-10-14 · `defining-problems` 기준 + 딥리서치 4갈래(기술 층위·표준 / 현장 사례 / 공급 구조·해외 / 정책·행위자) · 상태: 검증 예정 가설

## 0. 먼저 알아둘 것

**호환 문제는 기관·의원이 반복해서 지적한 구조 문제이고, 농가가 겪는 것은 확인되지 않았다.** 조사 결과는 이렇다.
- 현장 사건은 익명 1건(딸기 농가 추가 비용 500만 원, 2024.3 뉴스서울)뿐이다. 장비명·지역·규모가 없고 농진청 아라온실 소개 맥락의 홍보성 예시일 가능성이 높다. 같은 사례를 인용한 다른 매체는 이 기사를 되풀이할 뿐이다.
- 농가의 직접 발언, 전면 교체 사례, 변환기 같은 임시방편은 못 찾았다(없다는 뜻이 아니라 이번에 못 찾았다는 뜻).
- 농가가 체감하는 도입 제약 1위는 초기비용(딸기 70농가 설문 62.8%, 농식품부 조사 53.8%)이고, 호환성은 선택지에 보이지 않았다. 미도입 딸기 농가의 신규 도입 의향은 5점 만점에 1.7~1.9점이다.
- 인터뷰 두 곳 모두 호환 피해를 말하지 않았다.

**귀무 가설(모든 가설의 공통 위험 가정):** 호환 문제는 구조적으로 존재하지만 딸기 단동 농가의 체감 우선순위 안에 들지 않는다. 아래 가설 1~5는 이 귀무 가설이 기각될 때만 성립한다.

### 이전 문서 정정

- 「번호별 문제정의 1~5 딥리서치 검증」의 정의 1에서 500만 원 건을 "딸기 농가 사례 1건"으로 올렸는데, 위 이유로 근거 강도가 더 낮다. 독립 근거로 쓰지 않는다.
- 「스마트팜 장비 호환·유지보수 문제정의」의 정의 4 전제("업체가 사후관리 의무를 진다")와 정의 3 ⑤의 "방치"는 근거가 없다(이미 검증 문서에서 수정한 내용).
- KS X 3265는 "못 찾았다"가 아니라 구동기 인터페이스 표준으로 실재한다(제정연도 `[미확인]`).

## 2. 번호별 가설

각 가설은 `①사용자 ②상황 ③하려는 일 ④장애 ⑤이유와 비용` 순이며, 해결책을 문장에 넣지 않았다.

### 가설 1. 신축 시점에만 걸리는 표준 — 기존 설치분의 사각지대

| 칸 | 내용 |
|---|---|
| ① 사용자 | 표준 의무화 이전에 장비를 설치하고 시즌마다 기능을 덧붙이는 단동 시설딸기 농가 `[진술: 점진적 자동화]` |
| ② 상황 | 이미 설치된 장비 위에 양액·개폐 같은 기능을 추가하거나 부품을 교체할 때 |
| ③ 하려는 일 | 기존 장비를 버리지 않고 한 체계로 운영하기 |
| ④ 장애 | 표준 의무는 신축 시점 장비에만 걸려 있고 기존 설치분에는 소급되지 않아, 업체 간 연동 여부를 장비마다 따로 확인해야 한다 `[열람: 지침 신축 한정]` |
| ⑤ 비용 | 추가 연동·교체비 `[확인-요약: 500만 원 단건, 독립 근거 아님]`, 동별 수동 병행 시간 `[가정]` |

- 근거 강도: 구조 `[열람]` / 현장 `[요약, 단건]` / 행동 없음
- 반증 조건: 농가 두세 곳이 증설·교체 때 "같은 업체로 통일하면 그만이라 별도 비용이 없었다"고 한다.
- 가장 싼 확인: A 농가에게 "설치된 장비가 몇 개 업체 것이에요? 새 기능을 달 때 기존 장비와 안 맞아서 따로 하신 일이나 추가로 낸 돈이 있어요?"

### 가설 2. 통신은 표준이지만 소프트웨어·앱 층위는 비어 있다

| 칸 | 내용 |
|---|---|
| ① 사용자 | 국가표준 적합 기자재를 서로 다른 업체에서 구매한 시설딸기 농가 |
| ② 상황 | 적합 인증 제품끼리 하나의 제어·모니터링 화면으로 묶으려 할 때 |
| ③ 하려는 일 | 업체와 무관하게 한 화면·한 계정에서 환경을 보고 제어하기 |
| ④ 장애 | 표준이 통신 인터페이스까지만 다루고 데이터 의미 매핑·제어 로직·앱/클라우드 계정은 업체별로 따로여서, 인증 제품끼리도 한 화면에 묶이는지는 업체 설명에 의존한다 `[열람: 통신 표준 범위] / [가정: 소프트웨어는 업체별]` |
| ⑤ 비용 | 업체별 앱을 따로 열어 보는 시간, 통합 연동 개발·설정비 `[가정]` |

- 근거 강도: 구조 `[열람: 표준 범위 공백]` / 업체 폐쇄의 직접 증거 `[미확인]` / 현장·행동 없음
- 반증 조건: 국내 주요 제어기 3~4개 업체 중 타사 센서·구동기를 공개 API 또는 표준 모드버스로 연동하는 사례가 일반적이다.
- 가장 싼 확인: 주요 제어기 업체의 매뉴얼·API·약관 공개 여부를 직접 열람(1~2일), 농가에게 "앱이 몇 개 깔려 있어요?"

### 가설 3. 업체가 사라질 때 데이터·설정이 함께 사라진다

| 칸 | 내용 |
|---|---|
| ① 사용자 | 영세 업체의 제어기·클라우드를 쓰며 생육·환경 데이터를 쌓아 온 시설딸기 농가 |
| ② 상황 | 설치 업체가 폐업하거나 서비스를 종료해 다른 업체 시스템으로 옮기려 할 때 |
| ③ 하려는 일 | 지난 시즌 데이터와 제어 설정을 가지고 새 시스템으로 이어 가기 |
| ④ 장애 | 데이터 소유·이전 규정이 법·계약에서 불명확하고 포맷이 업체 고유여서 옮길 수 있는지 알 수 없다 `[요약: KREI 소유 법리 공백] / [미확인: 반환 규정]` |
| ⑤ 비용 | 이력 손실로 다음 시즌을 0에서 시작 `[가정]`, 대체 장비 구입비 `[가정]` |

- 근거 강도: 구조 `[요약]` / 폐업 후 농가 사례 `[미확인]` / 행동 없음. 해외 사례(미국 Freight Farms 파산, 클라우드 종료)는 구조적 유사 사례일 뿐 한국 근거가 아니다.
- 반증 조건: 농가가 데이터를 업체 클라우드가 아닌 자기 파일로 따로 쓰지 않고 데이터를 활용하지도 않는다(실태조사에서 데이터 활용 경영체 비율이 낮음). 그렇다면 이전할 데이터 자체가 작다.
- 가장 싼 확인: A 농가에게 "지금 기록이 남는 데이터가 있어요? 그걸 따로 저장하거나 쓰세요? 업체가 바뀌면 어떻게 하실 건가요?"

### 가설 4. 호환 문제가 났을 때 누가 책임지고 누가 비용을 내는지 규정이 없다

| 칸 | 내용 |
|---|---|
| ① 사용자 | 여러 업체 장비가 섞인 시설을 운영하는 시설딸기 농가와 이를 지원하는 농기센터 지도사 |
| ② 상황 | 장비 간 연동이 안 되어 원인을 찾아야 할 때(센서인지, 제어기인지, 연결인지) |
| ③ 하려는 일 | 원인을 특정하고 누군가가 보수하게 하기 |
| ④ 장애 | 시공 하자는 건산법에 따라 시공사가 지지만 호환 불일치는 하자 범위에 들지 않고, 장비 사후관리 5년은 농가 의무로만 적혀 있어 호환 비용 귀속 규정이 없다 `[열람]` |
| ⑤ 비용 | 원인 진단에 쓰는 시간과 업체 간 책임 공방 `[가정]`, 자가정비 교육 참여 시간 `[요약: 광주 약 120명, 호환 한정 아님]` |

- 근거 강도: 구조 `[열람: 규정 공백]` / 현장 사례 `[미확인]` / 행동 일부(자가정비 교육, 호환 한정 아님)
- 반증 조건: 설치 업체가 호환 문제를 무상으로 해결해 주는 것이 관행이다(농가가 책임 공방을 겪은 적이 없다).
- 가장 싼 확인: 농가에게 "장비끼리 안 맞았던 때 누구에게 연락하셨고, 누가 어떻게 해결했어요? 비용은 누가 냈어요?" + 농기센터 지도사 2~3명에게 같은 질문.

### 가설 5. 구매 전에 기존 장비와 붙는지 판별할 근거가 업체 설명뿐이다

| 칸 | 내용 |
|---|---|
| ① 사용자 | 이미 장비를 쓰고 있는 상태에서 새 장비를 추가 구매하려는 시설딸기 농가 |
| ② 상황 | 구매 결정 시점에 기존 장비와 연동되는지 판단해야 할 때 |
| ③ 하려는 일 | 연동 실패에 따른 추가 비용을 피하고 구매하기 |
| ④ 장애 | 국가표준 적합 인증은 통신 인터페이스 범위이고 2026~2028년에는 의무가 아닌 "우선 사용"이어서, 구매 시점에 판별할 근거를 업체 설명 외에 얻기 어렵다 `[열람: 지침 문언] / [가정: 판별 수단이 업체 설명뿐]` |
| ⑤ 비용 | 연동 실패 시 추가 설치·교체비 `[가정]`, 구매 전 비교·확인에 쓰는 시간 `[가정]` |

- 근거 강도: 구조 `[열람: 우선 사용 문언]` / 현장·행동 없음. 이 가설이 가장 `[가정]` 비중이 높다.
- 반증 조건: 농가 대부분이 "설치 업체 한 곳에서만 산다"고 해 구매 시점에 판별할 일이 없다.
- 가장 싼 확인: "마지막으로 새 장비를 사거나 달 때, 기존 것과 맞는지 어떻게 확인하셨어요? 틀린 적이 있어요?"

**행동 증거가 있는 가설이 하나도 없다.** 가장 먼저 검증할 가설은 구조 근거가 가장 단단한 **가설 1**이고, 같은 전화로 가설 4·5를 함께 묻는 것이 가장 싸다. 가설 2는 인터뷰가 아니라 업체 문서 열람으로, 가설 3은 데이터 활용 여부에 따라 우선순위가 갈린다.

## 4. 이번에도 열지 못한 것 (인용 금지)

- 시설보급(ICT 시설보급·시설원예 현대화) 시행지침 원문. 농림사업정보시스템이 503이었고 온실신축 지침의 KS 조항이 같은지 모른다.

## 5. 보류한 해결책

통합 게이트웨이·어댑터, 호환 인증 확대·소급 적용, 설치 계약서 표준 조항, 데이터 이전·반환 의무 제도화, 구매 전 호환 체크 도구, 호환성 성과지표. 이 해결책들은 가설이 검증되기 전까지 문제 문장에 넣지 않는다.
