# MECE, 이슈 트리, 로직 트리

4단계(프레임)와 5단계(문장) 사이에서 읽는다. 문제 영역이 넓어 ①을 한 부류로 못 좁혔을 때, 사용자가
MECE·이슈 트리·로직 트리·"쪼개 달라"고 했을 때 쓴다. 출처와 시간 표시는 `sources.md`.

세 도구는 한 줄로 이어진다.

> **MECE**(나누는 규칙) → **이슈 트리**(문제가 어디에 있는지 영역을 나눠 훑고, 한 가지를 고른다)
> → **로직 트리**(고른 가지를 왜·무엇이 참이어야 하는지로 풀어 확인할 가설로 만든다) → **문장 칸 ①~⑦**

이슈 트리는 겉모습이고 그 밑에서 도는 규칙이 MECE다. MECE가 깨진 트리는 마인드맵일 뿐이다.
이 스킬에서 로직 트리는 이슈 트리에서 고른 노드를 근거 있는 가설 구조로 바꾸는 단계다 `[조합]`.

## 1. MECE 검사

노드 하나를 쪼갤 때마다 아래 네 가지를 통과해야 한다. 하나라도 걸리면 그 층을 다시 나눈다.

| 검사 | 묻는 말 | 걸리는 예 |
|---|---|---|
| ME (상호배타) | 한 사례가 두 가지에 동시에 들어가는가 | 업종 "음식점"과 "프랜차이즈"는 겹친다 |
| CE (전체포괄) | 가지를 다 합치면 부모가 되는가. 빠지는 사례가 있는가 | 10대~60대로 나누면 7세 이하와 70대 이상이 빠진다 |
| 기준 하나 | 이 층은 한 기준으로만 나눴는가 | 연령과 성별과 업종이 한 층에 섞였다 |
| 층위 | 가지끼리 같은 높이인가 | "음식점·편의점·만원센터"처럼 업종과 가게 규모를 섞음 |

- **1 대 99는 MECE지만 쓸모가 없다.** "화면 / 화면 외"는 맞지만 한쪽이 전부다. 한 기준으로 대체로 5개
  안팎, 비슷한 크기로 쪼갠다. 둘로 나눠도 되지만 둘이어야 하는 것은 아니다.
- **꼬임.** 첫 층에서 "거주 형태"를 뽑아 놓고 둘째 층 다른 가지에 "거주 형태"가 또 나오면 한 가지를
  쪼갠 것이다. 한 군데로 모으고 가지를 다시 짠다.
- **의사결정에 도움이 되는가.** 이론상 맞아도 결정에 안 쓰이는 층(예: 집을 고르는데 국내/해외)은
  기각 사유를 적고 접는다. 기각은 근거를 적고 하며, 느낌으로 처음부터 빼지 않는다.
- **빠진 것이 결정을 깬다.** 가격 가지를 빼고 만든 집 고르기 트리는 쓸 수 없다. 끝낸 뒤 "이 문제의
  결정에 꼭 필요한 항목이 안 들어갔는가"를 한 번 더 묻는다.

### 나누는 기준을 찾는 손잡이

| 쓰는 곳 | 기준 후보 |
|---|---|
| 모든 것 | 안 / 밖 · 사람 / 환경 · 공급 / 수요 · 전 / 중 / 후(before·during·after) · 입력 / 출력 · 겉 / 속 |
| 사물 | 하드웨어 / 소프트웨어 · 오감 · 주 장치 / 주변기기 |
| 사람 | 연령(경계값을 숫자로) · 성별 · 내국 / 외국(외국은 국가·대륙으로 한 번 더) |
| 사업 | 가치사슬 단계(생산→수확→1차 가공→보관→가공→배송·포장→판매→사후) · 1/2/3차 산업 |
| 행위자 | 사용자 · 직원 · 관리자 · 제작자 · 규제 기관 · 공급 업체 |

세상을 나누는 렌즈는 많고 쓰는 렌즈가 답의 모양을 정한다(생물/무생물은 과학자의 렌즈이고, 돈이 되는
쪽을 찾는 사람에게는 산업·가치사슬 렌즈가 쓸모 있다). **렌즈 후보를 2~3개 만든 뒤 하나를 고르고,
고르지 않은 렌즈는 다음 판으로 남긴다.** 한 기준으로 안 풀리면 판을 여러 개 그려도 된다.

## 2. 이슈 트리 설계

| 단계 | 하는 일 | 완료 기준 |
|---|---|---|
| 1. 루트 | 현재 상태와 이상 상태의 간극을 한 문장으로 쓴다. 비교할 두 쪽이 다 있어야 한다 | 해결책 이름이 없고, "~가 문제"가 아니라 "~인데 ~여야 한다" 꼴이다 |
| 2. 첫 층 | 렌즈 후보 2~3개 중 하나로 가장 크게 영향을 주는 A, B, C를 나눈다. 이 층이 틀어지면 전체가 틀어진다 | 1절 네 검사를 통과, 노드가 층위가 같다 |
| 3. 아래로 | 같은 규칙으로 A-1, A-2…, A-1-1…을 쪼갠다. 노드 번호는 계층을 드러낸다 | 5층 안팎. 행동할 수 있는 단위(원자)까지 |
| 4. 가지 정리 | 노드마다 `유지 / 기각 / 보류`와 사유·근거 등급을 쓴다 | 기각이 `[가정]`이면 기각이 아니라 보류 |
| 5. 영향력 평가 | 기준 3개(예: 용이성·비용·임팩트)와 가중치로 리프를 점수 낸다 | 가중치 합 100%, 점수 근거 한 줄 |
| 6. 고르고 다시 | 높은 리프 하나를 새 루트로 삼아 3단계를 되풀이한다 | 선택한 경로가 ①·②·④로 읽힌다 |

- **깊이는 "행동이 바뀔 때까지"다.** 키오스크 문제는 "하드웨어 → 외부 하드웨어 → 키패드 → 점자 키패드"까지
  내려가야 실제 손이 움직이는 단위가 나온다. 3개가 나왔으니 MECE라고 멈추지 않는다.
- **리스트가 안 닫히는 문제는 판단한다.** 사회 문제는 항목이 딱 떨어지지 않을 수 있다. 그때는 "기타"
  가지를 두거나 판단이라고 밝힌다. 닫혔다고 쓰지 않는다.
- **트리를 쓴 사람이 현장을 봤는가.** 키오스크를 열어 보지 않고 쪼갠 트리는 내부 노드가 비어 있다.
  노드마다 `[확인]`(본 것) / `[진술]`(들은 것) / `[가정]`(지어낸 것)을 붙이고, `[가정]`이 많은 가지는
  "열어 볼 것"으로 적는다.
- **AI에게 시킬 때.** 노드 개수만 지정하면 축이 아니라 박스만 늘어난다. "기준(축)을 먼저 선언하고, 그
  축 아래로만 나열하고, 위에서 아래로 흐르게 그려라"로 쓴다. 먼저 손으로 한 번 쪼갠 뒤에 시킨다.
- **보이는 곳 밖을 본다.** 대상 자체(안)를 쪼갠 뒤 대상을 둘러싼 것(밖: 사용자, 장소, 직원, 제작자, 규제)을
  쪼갠다. 밖의 가지 중에 내가 영향을 줄 수 있는 쪽(제작자냐 사용자냐)이 고객이 누구인지를 정한다.

## 3. 로직 트리 설계

이슈 트리에서 고른 리프(또는 경로)를 받아, **그것이 참이려면 무엇이 참이어야 하는가**로 한 번 더 푼다.
이슈 트리가 "어디"를 가렸다면 로직 트리는 "왜"와 "무엇을 확인할지"를 가른다.

| 항목 | 규칙 |
|---|---|
| 루트 | 이슈 트리에서 고른 리프를 평서문 가설 하나로 쓴다: "[누가]는 [어디서] [무엇] 때문에 [비용]을 치른다" |
| 자식 | "이게 참이려면 무엇이 모두 참이어야 하는가"를 MECE로 쓴다. 자식 사이는 AND인지 OR인지 표시한다 |
| 깊이 | 왜를 다섯 번. 마음이 아니라 조건에 닿으면 멈춘다. 5번이 기계적이면 안 된다 |
| 리프 | 하루 안에 확인할 수 있는 한 문장. 확인할 사람·기록과 근거 등급을 붙인다 |
| 판정 | 리프가 하나라도 거짓이면 그 가지는 접고 이슈 트리의 다음 리프로 돌아간다 |

로직 트리의 리프 중 틀리면 정의가 무너지는 것 3개가 곧 템플릿의 `가장 위험한 가정`이다.
리프를 묻는 말은 미래 의향이 아니라 과거 행동으로 쓴다(`interviews.md` 5절).

두 트리 모두 길들여진 문제만 확정하는 도구가 아니다. 사악한 문제에서도 "빠진 곳 없이 훑는" 용도로는
쓰되, 트리의 원인 구조를 정답으로 내지 않는다. 같은 문제의 트리를 다른 렌즈로 한 번 더 그려 본다.

## 4. 문장 칸과 이어 붙이기

선택한 경로 하나를 위에서 아래로 읽으면 문장이 된다.

| 트리의 위치 | 문장 칸 |
|---|---|
| 이슈 트리 선택 경로에서 "누구"에 해당하는 노드 | ① 사용자 |
| 경로에서 "언제·어디서"에 해당하는 노드 | ② 상황 |
| 루트의 이상 상태 | ③ 하려는 일 |
| 로직 트리에서 조건에 닿은 가지 | ④ 장애 |
| 영향력 평가에서 센 값, 로직 트리의 비용 리프 | ⑤ 이유와 비용 |
| 이슈 트리의 "지금 하는 행동" 노드 | ⑥ 현재 대응 방식 |
| 로직 트리에서 ⑥으로 안 풀리는 리프 | ⑦ 한계 |
| 로직 트리의 `[가정]` 리프, 기각된 가지 | 비운 칸, 가장 위험한 가정, 프레임 비교의 버린 프레임 |

노드마다 ①~⑦ 어디에 쓰이는지 적히지 않으면 트리는 장식이다. 경로가 문장이 안 되면 단계 2의 렌즈가
틀렸을 가능성을 먼저 의심한다.

## 5. 산출 형식

들여쓰기 번호 트리로 쓴다. 노드 한 줄은 `번호 이름 · 판정 · 근거 등급`이다.

```
루트: <현재 상태와 이상 상태의 간극 한 문장>
렌즈: <고른 기준> (검토한 렌즈: <후보 2개>)
A. <노드> · 유지 · [진술]
  A-1. <노드> · 보류 · [가정]
    A-1-1. <리프> · 유지 · [확인: 출처]
B. <노드> · 기각: <사유> · [확인]
C. 기타 · 보류 · [가정]
```

그 뒤에 두 표를 붙인다.

| 리프 | 용이성 | 비용 | 임팩트 | 점수(가중 합) | 근거 |
|---|---|---|---|---|---|
| (가중치 %) | 30 | 40 | 30 | | |

| 로직 트리 리프(확인할 문장) | 틀리면 | 가장 싼 확인 | 등급 |
|---|---|---|---|

MECE 자가 점검 한 줄을 붙인다: "층마다 ME·CE·기준 하나·층위 통과. 못 한 층: <층, 이유>".
통과를 못 한 층이 있으면 그 사실을 먼저 적는다.

## 6. 흔한 실수

| 이렇게 쓰게 된다 | 이렇게 고친다 |
|---|---|
| 떠오르는 대로 가지를 뻗는 마인드맵 | 층마다 한 기준을 선언하고 ME·CE를 점검한다 |
| 첫 층에 연령·성별·업종을 섞는다 | 층마다 기준 하나. 다른 기준은 다른 판으로 |
| 3개 나왔으니 끝났다고 멈춘다 | 행동 단위(원자)가 나올 때까지, 5층 안팎 |
| 근거 없이 느낌으로 가지를 처음부터 뺀다 | 기각 사유와 근거 등급을 적고, `[가정]`이면 보류 |
| 층위가 다른 것을 나란히 둔다 | 위계를 맞추고, 한 가지의 하위를 위로 올리지 않는다 |
| 같은 것이 다른 가지에도 나온다 | 한곳으로 모으고 가지를 다시 짠다 |
| 인터뷰만 많고 대상을 열어 본 적이 없다 | 내부 구조를 직접 보거나 자료로 보고, 안 본 가지는 `[가정]` |
| 트리가 문장과 안 이어진다 | 4절의 표로 노드를 칸에 붙인다. 안 붙으면 렌즈를 바꾼다 |
| AI에게 "노드 7개"만 시킨다 | 기준(축)을 먼저 정하고 그 축 아래로만 나열시킨다 |

## 7. 적용 예: 시설딸기 스마트팜 호환 문제

모든 노드가 구조 분류이므로 아래 판정 칸은 모두 `[가정]` 이상을 넘지 않는다. 형식을 보이는 예시다.

```
루트: 시설딸기 농가는 장비를 늘리고 싶어도 서로 맞는지 확인하는 데 시간과 돈을 쓴다(체감 미검증)
렌즈: 안 / 밖 (검토한 렌즈: 가치사슬 단계, 행위자별)
A. 장비 사이의 문제(안) · 유지 · [가정]
  A-1. 통신 인터페이스가 안 맞는다 · 보류 · [확인: KS X 3265~3267 존재] 농가 체감 [가정]
  A-2. 제어 로직·앱·클라우드 계정이 안 맞는다 · 보류 · [가정]
B. 장비 밖의 문제 · 유지 · [가정]
  B-1. 구매 시점: 의무가 신축 시점에만 걸림 · 유지 · [확인: 온실신축 지침] 시설보급 지침은 미열람
  B-2. 업체: 설치·사후관리 업체가 다르다 · 보류 · [가정]
  B-3. 농가: 연동 확인 비용을 누가 내는지 규정 없음 · 유지 · [확인: 온실신축 지침]
```

- 로직 트리는 B-1을 루트로 "농가가 증설 때 연동을 따로 확인한다 → 확인에 시간·돈을 쓴다 → 쓴
  적이 한 번이라도 있다"로 풀고, 마지막 리프를 A 농가에게 과거 행동으로 묻는다.
- 마지막 리프가 거짓이면 B-1을 접고 다음 리프(B-3)로 돌아간다. 모두 거짓이면 반증 조건을 채택한다.
