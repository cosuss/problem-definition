# 산출물 템플릿

6단계에서 쓴다. 절의 이름과 순서를 그대로 쓴다. 분량은 표가 대부분을 차지하게 하고, 표 밖의 설명은
절마다 세 줄 이하로 쓴다. 표의 칸은 한 문장으로 채운다. 해당 없는 절은 지우지 않고 `해당 없음: 이유` 한 줄로 둔다.

사용자가 한 문장만 원하면 `문제 정의문`, `가장 위험한 가정`, `보류한 해결책` 세 절만 낸다.
과제 양식이 따로 있으면 내용을 그 양식의 칸에 옮기되 근거 등급과 `가장 위험한 가정`은 남긴다.

```markdown
# 문제 정의: <한 줄 제목 — 해결책 이름을 넣지 않는다>

## 문제 정의문
①이 ②에서 ③을 하려 할 때, ④ 때문에 ⑤를 치른다. (칸을 실제 내용으로 채운 한 문장)

| 칸 | 내용 | 근거 |
|---|---|---|
| ① 사용자 | | [확인: 출처] / [진술] / [가정] |
| ② 상황 | | |
| ③ 하려는 일 | | |
| ④ 장애 | | |
| ⑤ 이유와 비용 | | |

- 비운 칸: <칸 번호와, 채우려면 무엇을 누구에게 확인해야 하는가. 없으면 "없음">
- 사용자나 장애가 갈리면 `## 문제 정의문 1`, `## 문제 정의문 2`…로 나누고 근거가 단단한 순서로 번호를 매긴다.
- 상태: 확정본 | 잠정본 | 현재 채택한 정식화 (성격 진단에 따라)
- 겪는 사람 / 대가를 내는 사람: <같으면 한 번만>

## 현상
| 관찰된 것 | 근거 |
|---|---|
| <현재 상태. 누가, 언제·어디서, 얼마나 자주> | [확인: 출처] / [진술] / [가정] |
| <지금 버티는 방식(우회 행동)> | |
| <이미 시도한 대책과 결과> | |

- 목표 상태: <어떻게 되면 좋은가>
- 간극: <현재와 목표의 차이. 가능하면 셀 수 있게>

## 문제의 성격
<한 줄 진단: 길들여진 / 가정이 많은 / 열린 / 사악한 문제 + 발생·탐색·설정형>
<창업 맥락이면: 고객과 문제의 관계 — 발등의 불 / 굳어진 현실 / 미래 비전, 그 근거가 된 행동>
이 때문에: <산출물에서 달라진 점 한 줄>
<lenses.md 표의 '산출물에 더 넣는 것'을 여기에 이어서 적는다: 손실 한도, 이해관계자별 좋다/나쁘다, 멈춤 기준 등>

## 왜 되풀이되는가
<3단계를 했을 때만. 패턴 → 구조 2~4문장, 시도한 대책이 해당하는 함정과 그것이 밀어낸 것>

## 프레임 비교
| # | 프레임 (누구의, 어떤 문제로 보는가) | 전제하는 해결 방향 | 채택 여부와 이유 |
|---|---|---|---|
| 1 | <사용자가 처음 가져온 프레임> | | |
| 2 | | | |
| 3 | | | |

## 좋은 문제 판정
| 조건 | 판정 | 근거 |
|---|---|---|
| 절실성 | 강함 / 약함 / 모름 | |
| 구체성 | | |
| 반복성 | | |
| 규모 | | |
| 해결 가능성 | | |
| 비대칭성 | | |
| 확장성 | | |

## 가장 위험한 가정
틀리면 정의가 무너지는 순서로 3개.

| 가정 | 틀리면 | 가장 싼 확인 방법 |
|---|---|---|
| | | <누구에게 무엇을 묻는가 / 어떤 기록을 보는가. 하루 안에 할 수 있는 것부터> |

- 반증 조건: <무엇이 관찰되면 이 정의를 버리고 프레임 #N으로 옮기는가>

## 보류한 해결책
<사용자가 가져온 해결책과 도중에 떠오른 것. 평가하지 않고 적어 둔다.>
<각 해결책이 프레임 표의 어느 행을 전제하는지 번호로 표시한다.>
```

## 쓰는 요령

- 근거 등급은 표의 근거 칸과 문장 끝에 붙인다. 문제 정의문 자체에 `[가정]`인 칸이 있으면 그 칸 뒤에 붙인다.
- `가장 싼 확인 방법`은 일반 조언("인터뷰를 하세요")이 아니라 누구에게 무슨 말을 물을지까지 쓴다.
  묻는 말은 미래의 의향("쓰시겠어요?")이 아니라 과거의 행동("지난번에 그 일이 있었을 때 어떻게 하셨어요?")을 묻게 한다.
- 초안 모드에서 `[가정]`이 정의문의 절반을 넘으면 맨 위에 한 줄로 밝힌다:
  "이 초안은 가정 위에 서 있다. 아래 세 가지를 확인하면 등급을 고치고, 확인하지 못했으면 등급 표시를
  남긴 채 '검증 예정 가설'로 제출한다." 마감이 있는 사람에게는 가설임을 밝힌 초안이 낼 수 있는 결과물이다.
- 수치를 지어내지 않는다. 모르는 수치 자리는 `[확인 필요: 무엇의 수치, 어디서 찾는가]`로 둔다.

## 후보 모드의 산출물

인터뷰 기록에서 후보를 뽑을 때는 위 템플릿 대신 아래 구성을 쓴다. 후보 하나가 정해진 뒤에 위 템플릿으로 넘어간다.

```markdown
# 문제 정의 후보: <대상 — 해결책 이름을 넣지 않는다>

## 인터뷰에서 확인된 것
| 응답자 (조건) | 한 것 · 내놓은 것 | 평가 · 의향 |
|---|---|---|
| <지역, 규모, 판로 등 한 줄> | <과거 행동과 지금의 대처, 들인 시간·돈> | <불만, 의견, 하겠다는 말> |

## 기존 가설 대조
| 가설 | 지지 | 반대 | 판단 |
|---|---|---|---|

## 후보
### 후보 N. <한 줄 이름>
> <①이 ②에서 ③을 하려 할 때, ④ 때문에 ⑤를 치른다. 칸마다 등급>

| 항목 | 내용 |
|---|---|
| 증거 | 지지: … / 반대: … |
| 지금의 대체재 | <무엇으로 버티는가, 충분한가> |
| 사분면 | <심각성 × 보편성, 근거 또는 모름> |
| 지불자 | |
| 가장 먼저 확인할 것 | <물을 말> |

## 후보 비교
| 후보 | 행동 증거 | 대체재로 충분한가 | 반복 | 왜 아직 안 풀렸나 | 다음 확인의 비용 |
|---|---|---|---|---|---|

## 다음에 검증할 순서
<1~3순위와 이유 한 줄씩. 인터뷰 인원이 적으면 "채택"이라 쓰지 않는다.>

## 다음 인터뷰에서 물을 것
<후보별로, 그 후보를 무너뜨릴 수 있는 질문. 누구에게 묻는지 포함.>

## 보류한 해결책
```

후보는 3~5개, 후보마다 표 밖 설명은 세 줄 이하로 쓴다.
